# Brief de interfaz

1. Describe quién llega, qué tarea intenta completar y qué evidencia demuestra que terminó. Distingue requisito, decisión de diseño e hipótesis.
2. Dibuja primero el recorrido mínimo. Para cada pantalla, identifica acción primaria, datos imprescindibles y qué no entra en esta iteración.
3. Incluye estados vacío, cargando, error recuperable, sin permisos y éxito; especifica volver, cancelar y repetir cuando cambian datos. Define comportamiento en móvil sin copiar la matriz de escritorio.
4. Anota componentes existentes que se deben reutilizar y decisiones que requieren validación. Usa contenido plausible, sin datos reales.

Entrega el recorrido, inventario de pantallas, estados y criterios observables. No dupliques especificaciones de implementación si el usuario solo está explorando.
